# CloudLight Solutions

A React + Vite + TypeScript training website with an Express API. Salesforce is the flagship course, alongside MERN Stack, UI/UX Design and Python. Built from the supplied requirements, preserved in `docs/requirements.md`.

## Run locally

Requires Node.js 22.12+ (tested on Node 24).

```sh
npm install
cp .env.example .env
npm run dev
```

Website: http://127.0.0.1:5173 • API: http://127.0.0.1:3001

No service credentials are required for local use. Callback requests are saved to `backend/data/leads.jsonl`, a private, ignored file. The course assistant uses a multilingual knowledge-based responder by default; it is not represented as a connected LLM.

## Commands

```sh
npm run dev          # API and Vite together
npm run build        # Type checking, production build and SEO route documents
npm start            # Express serves the built website and API
npm test             # API, validation, persistence and assistant checks
npm run test:browser # Browser route, responsive, menu, chat and form checks; dev must run
```

Install the browser once with `npx playwright install chromium`. `node scripts/check-accessibility.mjs` checks representative pages with axe. `node scripts/check-themes.mjs` verifies both palettes, contrast, theme persistence, responsive layouts and chat. Both browser scripts expect the local website at port 5173.

## Configuration

Copy `.env.example` to `.env`. Frontend variables beginning `VITE_` are public and are compiled into the build; never put secrets in them.

- `VITE_PHONE`: the single phone configuration for phone/WhatsApp; default `+916382124970`.
- `VITE_CONTACT_EMAIL` / `VITE_CONTACT_ADDRESS`: replace the clearly labelled demo contact details before public launch.
- `VITE_SITE_URL`: canonical public website origin; default `https://cloudbytelabs.com`.
- `SITE_URL`: permitted browser origin for the API. Set to the public origin in production.
- `PORT` / `HOST`: API bind address. Use `HOST=0.0.0.0` only when required by your hosting provider.
- `TRUST_PROXY=1`: only when exactly one trusted reverse proxy sits in front of the API.
- `MONGODB_URI` / `MONGODB_DATABASE`: optional MongoDB lead storage. Without them, the file fallback requires a persistent disk.
- `DATA_DIR`: optional local lead directory; defaults to `backend/data`.
- `AI_API_KEY` / `AI_MODEL` / `AI_BASE_URL`: optional server-only, OpenAI-compatible chat provider. Both key and model are required. Provider failures show the contact fallback; fees and unavailable business facts are never fabricated.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `LEAD_NOTIFY_EMAIL`: optional lead notification email. Failure does not discard a saved lead. Without these values, no email is sent.
- `VITE_GA_ID`: optional GA4 measurement ID, inactive until consent.

## Deploy the full application

1. Configure the production environment and confirmed contact information.
2. Install dependencies with `npm ci` and run `npm run build`.
3. Start with `npm start` under a process supervisor or your Node hosting platform.
4. Put HTTPS in front of Express, set `SITE_URL` and `VITE_SITE_URL` to the real origin, and configure proxy trust only for your actual topology.
5. Use MongoDB Atlas or a persistent volume for local lead storage; ephemeral server disks will lose locally stored enquiries.
6. Configure SMTP if the team should receive notifications, and provide AI credentials if live LLM answers are desired.
7. Verify the public origin, API, consent and storage after deployment. For multiple application instances, replace the in-memory rate-limit store with a shared store.

Express serves the complete production application, APIs and route metadata. A static-only host will not execute the form/chat backend; proxy `/api` to the Express service if hosting the frontend separately.

This work is running locally; it has not changed DNS or deployed to cloudbytelabs.com. The optional browser agent curriculum lookup is feature-detected; native WebMCP validation requires a browser supporting `document.modelContext`.
